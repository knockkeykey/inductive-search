# 感应式查找

浏览器扩展名称：**感应式查找**。

这是基于 [tymscar/hunch](https://github.com/tymscar/hunch) 的公开派生项目，由 [knockkeykey](https://github.com/knockkeykey) 维护。本项目保留原作者 **Oscar Molnar（tymscar）** 的代码历史与 MIT 许可证。

原项目提供由 Jev 驱动的网页段落查找。本分支增加条件筛选、搜索范围、文档搜索，并接入 OpenRouter 与 OpenLux。

## 本分支新增的功能

| 功能 | 使用方式 |
| --- | --- |
| 按条件找原文 | 每行一个条件，最多 5 个；选择全部满足或任一满足 |
| 网页内高亮 | 结果直接在网页上高亮并标注分数；▲ / ▼ 或滚动条标记切换结果 |
| 搜索范围 | 整页、仅正文、当前选区；包括开放 Shadow DOM 和同源 iframe |
| 动态页面 | 搜索后页面新增内容（无限滚动、懒加载）时提示“新增 N”，只补搜新增部分；单页应用切换网址后提示重新搜索 |
| PDF 与 Word | 在 PDF 网页上按快捷键，用内置文档查看器打开并搜索；也可以打开本地 PDF、Word（.docx）文件。结果标注页码 |
| 关键词与阈值 | 按问题查找时，同时包含全部关键词的段落也会列出并标注“关键词”；相关度阈值可在 0.2–0.7 之间调整 |
| 失败重试 | 部分批次失败时出现“重试 N”，只重新发送没有得到分数的文字块 |
| API 服务商切换 | TypeSafe、OpenRouter、OpenLux 的 Key 和模型分别保存 |
| 中文输入与搜索状态 | 支持两字问题和输入法；手动提交搜索；区分无高相关结果与部分请求失败 |

新功能属于本分支，不表示上游已经合并或支持它们。

## 安装

需要 Node.js 20.19+、22.13+ 或 24+（开发依赖的要求）。

```sh
git clone https://github.com/knockkeykey/inductive-search.git
cd inductive-search
npm ci
npm run build
```

- **Chrome / Edge**：打开 `chrome://extensions` 或 `edge://extensions`，启用开发者模式，选择“加载未打包的扩展程序”，加载 `dist/chrome`。
- **Firefox**：在 `about:debugging#/runtime/this-firefox` 加载 `dist/firefox/manifest.json`，这是临时附加组件。
- 构建也输出 `dist/safari`；Safari 需要另行转换并打包，当前没有验证 Safari 的运行效果。

更新代码后重新构建并在扩展管理页重新加载；已经打开的网页建议刷新。

## 配置 API

打开扩展设置，选择服务商，粘贴该服务商的密钥，点击“保存”。

| 服务商 | 获取密钥 | 默认模型 | 搜索接口 |
| --- | --- | --- | --- |
| TypeSafe 官方 | [TypeSafe 控制台](https://console.typesafe.ai/keys) | `jev-latest` | `https://api.typesafe.ai/v1/systemone` |
| OpenRouter | [OpenRouter 密钥](https://openrouter.ai/settings/keys) | `~typesafe/jev-latest` | `https://openrouter.ai/api/v1/systemone` |
| OpenLux | [OpenLux 控制台](https://www.openlux.ai/login) | `jev-1.13.0` | `https://api.openlux.ai/v1/systemone` |

OpenRouter 可固定选择 `typesafe/jev-1.13`，接入依据为 [官方 TypeSafe SDK 指南](https://openrouter.ai/docs/guides/community/typesafe-sdk)。

OpenLux 使用 [Jev 专用 System One 文档](https://doc.openlux.ai/en/reference/typesafe/v1/systemone?leaf=c%3A1790771919883) 中的 `state` 和 `questions` 请求格式。模型菜单还提供站点通用示例中的 `jev-1.13.0:stable` 路由名，但该别名是否可用取决于账号权限，尚未用真实 Key 验证。该模型的专用接口为 `/v1/systemone`，不使用通用的 Chat Completions 示例。

这里调用的是 Jev 决策模型。GPT、Claude 等自由文本聊天模型不能直接替代它。

## 使用

macOS 按 **Option + F**，其他平台默认 **Ctrl + Shift + F**，也可以点击工具栏「感应式查找」图标。正常的 Cmd/Ctrl + F 保持不变。

Chrome 的快捷键在 `chrome://extensions/shortcuts` 修改；Firefox 可在扩展设置页修改。

### 按问题查找

选择“按问题”，输入问题，按 Enter 或点击“搜索”。支持中文两字输入；拼音确认不会提交请求。仅输入文字不会调用 API。

同时会在本地做关键词匹配：用引号（`"…"`、`“…”`、`「…」`）包住的短语按原样匹配；没有引号时，按空格拆成词，段落须包含全部词。单个字不参与匹配。模型分数低但包含关键词的段落也会列出，排在模型结果之后，并标注“关键词”。关键词结果在模型返回前就会显示。

例如：

- 哪一段写了小蝌蚪认错妈妈？
- 哪些内容提到了退款限制？
- 作者实际测试发现了什么？

### 按条件找

选择“按条件找”，每行写一个可由原文判断的条件，例如：

```text
描述作者实际进行的测试
包含具体数字或测量结果
```

- **全部满足**：同一文字块的每个条件分数都必须达到阈值。
- **任一满足**：至少一个条件达到阈值。
- 点击“搜索”提交；条件框中 Enter 换行，Cmd/Ctrl + Enter 提交。

Jev 为每个条件分别返回判断分数。全部满足取最低分、任一满足取最高分用于筛选和排序；这不是复合事件的校准概率。侧边栏显示每个条件的分数，方便检查判断。

条件应用于每个文字块。分散在不同段落的证据不会自动合并为“同一段满足全部条件”。

### 搜索范围

- **整页**：页面可提取的可见文字，包括导航和推荐区域。
- **仅正文**：优先提取 `article`，其次 `main` / 主内容区域；没有明确正文结构时使用整页并排除语义导航区域。自动识别可能不准确。
- **当前选区**：先在网页上划选文字，再打开感应式查找并选择这个范围。只提交选中的文字，保留其原文位置用于跳转。

每次提交都会重新提取范围内文字。整页和正文范围会读取开放 Shadow DOM（包括插槽内容）和同源 iframe；跨域 iframe、封闭 Shadow DOM 和尚未加载的内容不在提取范围中。

### 动态页面

搜索完成后，如果页面继续加载新内容（无限滚动、点击“展开更多”等），查找栏会出现“新增 N”按钮。点击后只把新增的文字块发给服务商，结果和之前的合并排序。页面变化本身不会自动发送请求。单页应用切换到另一个网址时，旧结果会作废并提示重新搜索。只监听顶层文档的变化；Shadow DOM 或 iframe 内部的新增内容需要重新搜索。

### 相关度阈值与失败重试

查找栏的“阈值”菜单默认 0.4，可选 0.2–0.7。调低会看到更多结果，也更可能不相关；调整只对已拿到的分数重新排序，不会发送请求。设置会保存。

部分批次失败（超时、限流、网络中断）时，查找栏会出现“重试 N”。点击后只重新发送这 N 个没有分数的文字块，已有分数保留并合并排序。

### PDF 与 Word 文档

- **网页上的 PDF**：在浏览器打开的 PDF 上按快捷键或点击图标，当前标签页会切换到感应式查找的文档查看器，读取文字后自动打开查找栏。网址不以 `.pdf` 结尾的 PDF（如 arXiv）也能识别。首次读取某个网站的文档时，需要点击“允许访问”，授予该网站的读取权限；浏览器的后退按钮可回到原 PDF。
- **本地文件**：在设置页点击“在文档查看器中打开”，选择或拖入 PDF、Word（.docx）文件。也可以直接对 `file://` 打开的 PDF 按快捷键，Chrome 需要先在扩展管理页打开“允许访问文件网址”。
- PDF 按页读取，每页以“第 N 页”作为所在标题，结果会标注页码。段落由文字位置推算，复杂排版（多栏、表格、脚注）可能被拆分或合并。
- Word 文档保留标题、列表、表格和内嵌图片，搜索时“所在标题”对应文档里的标题。
- 不支持：旧版 `.doc`（请另存为 .docx）、扫描版或纯图片 PDF（没有 OCR）。加密 PDF 会提示输入密码。
- 文档在本机转换，不上传文件；只有点击“搜索”时，提取的文字才会发给服务商。

### 查看结果

- 符合阈值的原文直接在网页上高亮并标注分数，不会在查找栏上方另开卡片。
- 底部 ▲ / ▼，或键盘 ↑ / ↓ 切换上一个、下一个结果，首尾循环；搜索框和网页正文获得焦点时都可使用。有结果时 Enter 切换到下一个结果，Shift+Enter 切换到上一个结果；修改问题后 Enter 提交新搜索，也可随时点击“搜索”重新搜索。输入法选字、条件框编辑、下拉框和设置控件保留原有键盘操作，右侧滚动条标记可直接跳转。
- 搜索状态和错误信息显示在查找栏底部单独的一行，长信息会完整换行，可选中复制。
- 再次按快捷键或按 Esc 关闭整个查找界面。

## 实现原理与边界

感应式查找提取页面文字并分块，给每个块生成 Jev `noul` 问题。后台把网页标题、网址、文字块和问题发给选定服务商，验证返回值后把评分发回网页。界面按阈值（默认 0.4，可调）筛选、排序并高亮原文，按问题查找时再合并本地关键词匹配。

评分反映模型对条件是否满足的判断，不是事实正确率，也不代表关键词出现次数。关键词匹配只是兜底，用于找回字面出现但模型分数低的段落，不影响模型分数。这个插件定位原文，不生成答案或推理解释。

长页按文字量和问题数量分批，最多 4 个请求并行。OpenLux 使用更小批次给条件问题留出空间；字符预算是估算，不是精确 token 计数。已完成批次会逐步显示；部分失败会明确提示结果不完整，并可只重试失败部分。

扩展不在每个网页预先注入脚本：按快捷键或点击图标时，借助 `activeTab` 只向当前标签页注入。

浏览器限制访问的页面（`chrome://`、`about:`、扩展商店等）无法使用。浏览器内置 PDF 阅读器无法直接搜索，会转到扩展自带的文档查看器。

## 开发与验证

```sh
npm test
npm run check
npm run watch
```

`npm run check` 依次执行类型检查、Biome 检查、构建和 Firefox 扩展校验。自动测试覆盖服务商路由、快捷键触发、条件组合与请求预算、范围边界、查找栏交互、搜索连接的关闭与中断、中文分句、Shadow DOM / iframe 提取、动态页面补搜。

自动测试使用模拟 API，不代表真实 Jev 的命中质量或账号额度已经验证。实际效果需使用自己的 Key，在目标网页上确认。

## 隐私与许可证

只有提交搜索时才向所选服务商发送当前范围的文字、页面标题、网址和问题。关闭搜索会取消客户端请求；已经被服务商接收的请求仍可能计费。

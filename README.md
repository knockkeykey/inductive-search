# 感应式搜索

**记不住关键词，也能用问题找到原文。**

正在看一篇文章，知道自己想找什么，却想不起作者用了哪个词？直接输入问题，感应式搜索会在当前网页中找出相关段落，在结果侧边栏展示原文，并带你跳回出处。你也可以把原文和来源保存为摘录，之后复制或导出。

它适合在评测中查找作者实际测试过什么，在技术文章中定位某个功能的说明，在协议里寻找额外费用，或在更新日志里筛选可能影响旧配置的改动。搜索结果来自你正在阅读的页面，便于核对原文和上下文。

感应式搜索用 Jev 判断模型为文字块打相关度分数，再由扩展筛选和排序。它用于定位原文，不生成新的答案或文章总结。扩展代码免费开源；搜索需要自己的 API Key，服务商可能按用量收费。

## 安装

需要 Node.js 20.19+、22.13+ 或 24+。

~~~sh
git clone https://github.com/knockkeykey/inductive-search.git
cd inductive-search
npm ci
npm run build
~~~

构建完成后，在浏览器扩展管理页加载对应目录：

- **Chrome / Edge**：打开 **chrome://extensions** 或 **edge://extensions**，启用开发者模式，选择“加载未打包的扩展程序”，加载 **dist/chrome**。
- **Firefox**：打开 **about:debugging#/runtime/this-firefox**，选择“临时加载附加组件”，加载 **dist/firefox/manifest.json**。
- **Safari**：构建会生成 **dist/safari**，但此目录的 Safari 运行效果尚未验证。

更新代码后重新构建并在扩展管理页重新加载；已经打开的网页建议刷新。

## 配置服务商

打开扩展设置，选择服务商，填入对应的 API Key 并保存。密钥和模型会按服务商分别保存在本机扩展存储中。

| 服务商 | 获取 API Key | 默认模型 |
| --- | --- | --- |
| TypeSafe | [TypeSafe 控制台](https://console.typesafe.ai/keys) | **jev-latest** |
| OpenRouter | [OpenRouter 密钥设置](https://openrouter.ai/settings/keys) | **~typesafe/jev-latest** |
| OpenLux | [OpenLux 控制台](https://www.openlux.ai/login) | **jev-1.13.0** |

模型菜单会提供服务商支持的 Jev 模型。OpenRouter 还可选择 **typesafe/jev-1.13**。OpenLux 的 **jev-1.13.0:stable** 路由名是否可用取决于账号权限。

这些服务商使用 Jev 的 System One 决策接口。GPT、Claude 等普通聊天模型不能直接替代 Jev。搜索只会发送到你当前选择的服务商。

## 开始查找

默认快捷键是 macOS 上的 **Option + F**，其他平台上的 **Ctrl + Shift + F**。也可以点击浏览器工具栏中的“感应式搜索”图标。普通的 **Cmd/Ctrl + F** 仍由浏览器处理。

快捷键可在扩展设置中修改；Chrome 会跳转到扩展快捷键设置页。

### 按意思找

选择“按意思找”，输入你真正想了解的问题，例如：

- “父亲去买什么了？”
- “作者实际测试过哪些功能？”
- “哪些段落提到了退款限制？”

按 Enter 或点击“搜索”。符合阈值的结果会显示在侧边栏，点击结果可跳回网页中的原文。分数用于表示段落与问题的相关程度，不代表事实正确率。

### 按条件找

选择“按条件找”，每行输入一个条件，最多五个。例如：

~~~text
作者实际进行过测试
给出了具体数据
~~~

“全部满足”会筛选同一文字块中每项条件都达到阈值的结果；“任一满足”会保留至少一项达到阈值的文字块。证据分散在不同段落时，不会自动合并判断为同一段满足全部条件。

结果侧边栏会展示各条件的分数。“全部满足”取各条件中的最低分，“任一满足”取最高分，用于筛选和排序。这些是查找用的组合分数，不是多个条件同时成立的校准概率。

### 选择搜索范围

搜索范围可以选：

- **整页**：读取页面可见文字，包括导航和推荐区域。
- **仅正文**：优先读取网页的正文区域；网页没有清楚标记正文时会退回整页。自动识别可能不准确。
- **当前选区**：先在网页中选中文字，再打开感应式搜索或选择当前选区，只搜索所选文字。

每次提交都会重新提取范围内文字。尚未加载的内容、iframe 内部和封闭 Shadow DOM 内容不在提取范围中。

## 查看与保存摘录

- 结果侧边栏展示符合阈值的原文、所在标题和条件分数；点击结果会定位到网页中的对应段落。
- **复制原文与来源**可复制段落、网页标题、网址和所在标题。
- **保存摘录**会把原文、来源、搜索条件和保存时间存到浏览器扩展的本地存储中。同一网址和原文不会重复保存。
- **已存摘录**支持查看、复制、单条删除和导出 Markdown。最多保存 500 条；达到上限时请先导出并清理。
- 摘录保存在本机，不会随搜索内容发送给服务商，也不会云同步。删除扩展会删除本地摘录，建议提前导出。

侧边栏可在“结果 / 摘录”视图间切换，也可以收起或展开。按 Esc 或再次按快捷键关闭查找界面。

## 实现方式与适用边界

扩展从当前网页读取文字并拆成文字块，再请 Jev 判断每一块是否符合问题或条件。拿到分数后，扩展负责筛选、排序和定位原文。

评分反映模型对相关性的判断，不是事实核验，也不代表关键词出现次数。这个版本没有精确关键词匹配兜底，因此原文出现某个词也不一定会出现在高相关结果中。使用时应回到原文核对上下文。

浏览器保护的页面（如 **chrome://**、**about:**、扩展商店和内置 PDF 阅读器）无法直接使用。

## 隐私

只有主动提交搜索时，扩展才会向所选服务商发送当前范围的文字、问题或条件、页面标题和网址。API Key 用于对应服务商的请求。已保存摘录留在本地，不会随搜索发送。

关闭搜索会取消客户端请求，但服务商已经收到的请求仍可能继续处理或产生费用。完整的数据处理和权限说明见[隐私政策](PRIVACY.md)。

## 开发与验证

~~~sh
npm ci
npm test
npm run check
npm run watch
~~~

**npm run check** 会依次运行类型检查、Biome 检查、构建和 Firefox 扩展校验。自动测试使用模拟 API；通过测试不能证明真实服务商的可用额度、延迟或实际命中质量。实际效果需要用自己的 API Key 在目标网页中确认。
